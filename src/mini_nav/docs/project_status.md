# mini_nav 项目状态

最后更新：2026-08-22
目标平台：ROS 2 Jazzy

`mini_nav` 是用于逐步理解移动机器人导航链路的自研学习项目。它以小而可验证的模块推进，并在后期与 `nav2_learning` 中的官方 Nav2 案例对照；`nav2_learning` 不属于本项目的运行依赖。

## 当前已完成

- `mini_nav_core`
  - 二维静态代价地图 `Costmap2D`。
  - 栅格坐标与世界坐标之间的转换。
  - 四邻域 A* 全局路径规划。
  - 代价地图与 A* 规划器的单元测试。
- `mini_nav_nodes`
  - 将静态代价地图发布为 `nav_msgs/msg/OccupancyGrid`。
  - 通过 RViz 的 `/initialpose` 和 `/goal_pose` 接收起点、终点。
  - 将 A* 结果发布为 `/mini_nav/global_path`。
- 可视化
  - 已有 RViz 配置可显示静态地图、全局路径和地图坐标轴。

## 当前边界

当前 A* 示例是静态地图上的规划与可视化演示，尚未构成可移动机器人的完整导航闭环。以下能力尚未接入：

- Gazebo Sim 仿真机器人。
- `/scan`、`/odom`、`/tf`、`/joint_states` 等机器人状态与传感器输入。
- 定位，以及由定位模块提供的 `map -> odom` 变换。
- 路径跟踪、碰撞规避、恢复行为和 `/cmd_vel` 速度控制。
- 动态代价地图、地图服务和 Nav2 生命周期管理。

因此，当前阶段不能把 `/mini_nav/global_path` 视为机器人可执行轨迹。

## 下一里程碑：Waffle 仿真接口基座

下一步只建立仿真接口，不实现自主运动：

1. 在 `mini_nav_bringup` 提供包内标准启动入口。
2. 复用系统安装的 `turtlebot3_gazebo`、`ros_gz_sim` 和 `ros_gz_bridge` 资源启动官方 TurtleBot3 Waffle。
3. 验证仿真向 ROS 2 提供 `/clock`、`/scan`、`/odom`、`/tf`、`/joint_states`，并可接受 `/cmd_vel`。
4. 不创建任何非零速度命令发布者；本里程碑仅验证接口和坐标系。
5. 保持 `astar_demo` 与仿真入口独立：静态 A* 示例不伪装成已定位的机器人导航。

### 接口与坐标系约束

- 固定使用 Waffle，以对齐现有官方对照案例和机器人尺寸。
- Waffle 的 `/cmd_vel` 消息类型是 `geometry_msgs/msg/TwistStamped`；后续控制器必须从该接口开始设计。
- 仿真阶段使用真实的 `odom -> base_*` 变换。
- 不发布静态 `map -> odom`。该变换必须由后续定位模块产生，避免引入错误的地图坐标语义。

## 后续学习顺序

1. **A* 可视化**（已完成）：静态地图、选点和全局路径。
2. **仿真接口基座**（下一步）：Waffle、时钟、TF、里程计、激光与速度接口。
3. **定位与坐标系**：理解并建立合法的 `map -> odom -> base_*` 链路。
4. **路径跟踪与安全停止**：将路径转换为受限速度命令，并加入目标到达、超时和零速度保护。
5. **代价地图与障碍处理**：利用激光数据构建局部代价地图。
6. **官方 Nav2 对照**：将自研模块与 `nav2_learning` 的 AMCL、规划、控制和恢复行为逐项比较。
